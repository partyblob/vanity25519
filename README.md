# Rust X25519 Vanity Key Finder

A multithreaded command-line vanity-key search tool implemented in Rust. It searches for X25519 public keys whose standard Base64 representation starts with a requested prefix, and includes a mode that looks for private keys with long runs of zero bytes.

The program uses a custom field-arithmetic and Edwards-point implementation, precomputed scalar-multiplication tables, incremental point stepping, and batch inversion to speed up candidate generation. Initial private-key material is obtained from the operating system CSPRNG through `rand::rngs::OsRng`; candidate keys are then generated by stepping through the scalar space.

## Requirements

- Rust and Cargo (install via [rustup](https://rustup.rs/))

## Build and test

```sh
cargo build --release
cargo test
```

## Usage

Run a case-insensitive, leetspeak-aware search with a bare prefix:

```sh
cargo run --release -- catflare
```

Or explicitly specify matching modes in a list:

```sh
cargo run --release -- "[i'sepples', s'Rust']"
```

List items are comma-separated. Quote the whole list so the shell passes it as one argument. The program also joins multiple positional arguments, which can be useful when composing the list in a shell.

### Prefix formats

- `i'Text'` — case-insensitive match with leetspeak alternatives (default).
- `s'Text'` — case-sensitive, exact Base64 characters.
- `'Text'` — shorthand for `i'Text'`.
- `Text` — bare-word shorthand for `i'Text'`; also supported outside a list.

Case-insensitive matching folds ASCII case and treats these pairs as equivalent: `e/3`, `a/4`, `s/5`, `g/9`, `i/1`, `o/0`, `b/8`, and `z/2`. Prefixes must be nonempty, use valid Base64 characters for their selected matching mode, and be at most 43 characters long.

### Search modes

```sh
cargo run --release -- --find-long
```

Searches for private keys with the longest consecutive run of zero bytes.

```sh
cargo run --release -- --bench
cargo run --release -- --bench --bench-n 256
```

Runs the scalar multiplication and incremental-stepping benchmarks. `--bench-n` controls the single-key sample count; use a positive integer.

With no arguments, the program prints a short usage summary. Vanity and long-zero searches use the available logical CPU count and refresh progress in the terminal. Vanity mode reports the closest prefixes found so far and stops when it finds a full match. Benchmark mode exits after printing its measurements.

## Output and key handling

Public and private keys are printed as standard Base64. Treat the private key as a secret: avoid saving terminal output to shared logs, shell transcripts, or other locations that are not protected. The long-zero mode also prints private keys for its best candidates.

## Security note

This is an experimental vanity-search program, not an audited cryptographic library. Its custom curve arithmetic and secret-dependent table lookups have not been independently reviewed for correctness or side-channel resistance. Do not use it as a general-purpose X25519 implementation or to protect high-value secrets.
